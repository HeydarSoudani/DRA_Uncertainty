# Belief Model Training

This page describes how the belief model is trained with the agent frozen: what is trained, the five phases of
`experiments/belief_model_training.py`, the files each phase writes, and what is still open (phase 0 and the RL
rewards).

The method follows Agent-BRACE ([arXiv 2605.11436](https://arxiv.org/abs/2605.11436),
[code](https://github.com/joykirat18/Agent-BRACE)) adapted to retrieval: the environment is the retriever, an
observation is the passages of one search, and the belief is one status per fixed criterion of the query.
Agent-BRACE trains the belief model and the policy together; here only the belief model is trained, and the
agent (glm, oss, ...) stays frozen.

## What is trained

The belief updater call of `src/belief_model_component` (`LLMBeliefUpdater`): b_t = f(query, b_{t-1}, o_t).
Its prompt holds the query, each criterion with its status and evidence, and the passages of the step not
judged before; its reply is the JSON list of updates. Criteria extraction and the query targeting scorer stay
frozen (prompted). A trained updater is used at inference with
`--belief-judge-model vllm/<served name>` and `BELIEF_VLLM_API_BASE=http://host:port/v1`.

## Phases

One phase per call; each reads the previous phase's output from `{output_root}/{run_name}/`.

| Phase | Does | Output |
|---|---|---|
| 0 | training queries, possibly from several datasets (**TODO**) | `phase0_queries/queries.jsonl` |
| 1 | frozen agent + teacher belief model, `monitor` mode; episodes and SFT samples | `phase1_trajectories/` |
| 2 | SFT warm-up of the student (LoRA, then merged) | `phase2_sft/merged/` |
| 3 | RL of the student (Agent-BRACE belief PPO; rewards **TODO**) | `phase3_rl/final/` |
| 4 | frozen agent with no / teacher / student belief model; existing evaluators | `phase4_eval/summary.json` |

```bash
python experiments/belief_model_training.py --phase 1 --run-name trqa_glm --agent glm
torchrun --nproc_per_node 4 experiments/belief_model_training.py --phase 2 --run-name trqa_glm
CUDA_VISIBLE_DEVICES=0 python experiments/belief_model_training.py --phase 3 --run-name trqa_glm
python experiments/belief_model_training.py --phase 4 --run-name trqa_glm --eval-splits trqa:wiki1:test,browsecomp_plus
# SLURM: sbatch --export=ALL,PHASE=1,RUN_NAME=trqa_glm scripts/run_belief_model_training.sh
```

### Phase 0: training queries (TODO)

Phase 1 reads `phase0_queries/queries.jsonl`, one query per line:
`{"qid", "dataset", "subset", "dataset_year"}` (the `dra_inference.py` arguments). Until phase 0 exists the file
is written by hand.

### Phase 1: teacher trajectories

For each split of the phase 0 queries, `dra_inference.py` runs the agent with the teacher belief model in
`monitor` mode on those queries only (`--query-ids-file`); inference resume applies. In monitor mode the agent
never sees the belief, so each run gives a fixed sequence of observations: the documents of every search, in the
order the belief model saw them.

Each `belief/{qid}.jsonl` becomes an episode. Document text is read back from the corpus (`CorpusLookup`), and
the teacher's saved replies are replayed through the inference updater code. This gives the exact prompt of every
teacher call and checks the replay against the saved `criteria_updates` (statuses, cited passages, span checks);
an episode is kept up to its first step that differs. Every teacher reply that parsed, and whose cited spans all
occur in their passage (`require_verified_spans`), is an SFT sample.

- `episodes.jsonl`: per query its criteria, per step the document ids and the teacher's reply, and how many steps
  the replay matched.
- `sft.jsonl`: `{qid, dataset, split, iteration, messages, completion}`.

### Phase 2: SFT

As Agent-BRACE's SFT script: the input is the chat-template prompt the inference server builds (native reasoning
off), then the teacher's reply and the end-of-turn token; the loss is on the reply only. LoRA (r=64, alpha=128,
all projections), lr 2e-5, 5 epochs, batch 4 x 8 accumulation per GPU, then merged into full weights.

### Phase 3: RL

A port of Agent-BRACE's `BeliefStateLMTrainer` in the setting of its recipes, outside veRL:

- **Samples.** The student re-tracks the belief over phase 1 episodes (`rl.env: replay`); every updater call is
  one sample, generated by vLLM at temperature 1.0 with its token log-probs. The episodes of a batch advance
  together, one batched generation per round. A reply that does not parse leaves the belief unchanged, as at
  inference.
- **Update.** One scalar reward per sample, whitened over the batch and given to every reply token; dual-clip
  PPO (clip 0.2, clip_c 3.0), token-mean, mini-batches of 4, one epoch, grad clip 1.0, AdamW lr 1e-5,
  full parameters in bf16. No critic, no KL to a reference (both off in Agent-BRACE's recipes; KL can be
  switched on).
- **One GPU.** vLLM sleeps during the update; the new weights go through `/dev/shm` and are reloaded in place.
- **Rewards: TODO** (`rewards.build_reward` raises). `rl.env: online` (the agent reading the student's belief)
  is TODO as well.

`metrics.jsonl` has one line per iteration (parse rate, reply lengths, PPO statistics, reward mean and spread).

### Phase 4: evaluation

For each split in `eval.splits`, three `dra_inference.py` runs of the frozen agent: `off` (no belief model),
`teacher` and `student` (that updater in `inform` mode; the student served by vLLM on `eval.serve_gpu`). The
criteria are the same in all runs. Scores come from each run's `summary.json`: answer accuracy (QA) or the
Auto-ARGUE nugget metrics (reports), and Recall@N and GradedRecall@N of the seen documents. In monitor mode
these scores would not depend on the belief model, which is why the evaluation uses inform mode.

## Settings

`experiments/configs/belief_model_training.yaml` has one section per phase plus `shared`. Precedence: defaults <
YAML < CLI flags < `--set section.key=value`. The CLI lists the shared flags first, then per phase the models
(agent, teacher, criteria, student, reward judge, evaluated model). The agent and retriever settings of phases
1 and 4 come from `experiments/configs/dra_inference.yaml` and are never repeated. Each phase saves its merged
settings as `phase{N}_config.yaml`.

## Code

`src/belief_model_training/`: `config`, `queries` (phase 0), `episodes` (episodes, `BeliefTracker`, teacher
replay), `trajectories` (phase 1), `sft` (phase 2), `rollout` (vLLM), `env`, `rewards`, `ppo` (losses from
veRL), `trainer`, `rl` (phase 3), `evaluate` (phase 4).

Phase 2 needs `peft`.

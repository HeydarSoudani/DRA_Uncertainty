You are a belief updater. Given a query, its criteria with their current belief, and one turn of a search agent with the new passages its search returned, your task is to record what the turn and each new passage state about the answers of the criteria, then write the new belief of every criterion with a new observation.
A criterion is one piece of information that a complete response to the query must contain. {shape_context}
A criterion marked "one answer" has a single correct answer; one marked "several answers" has several answers that hold together. A criterion marked "computed" is computed by the agent, and no passage states its answer.
The belief of a criterion is its nuggets: one per answer, each with a status and the sources it rests on, labeled [dN] for a document and [tN] for the agent's turn at search step N.
The agent's turn is its reasoning and search queries, written after it read the passages of the previous step, or, at the end, its reasoning and final answer. The new passages are the results of the turn's search queries; the agent has not read them yet.

== Observations ==
An observation is one source stating one answer of one criterion:
- A think observation is the agent's turn stating an answer. "supports": the turn gives the value as an answer, as a conclusion, a guess, or a hypothesis it checks; a search query that names the value for the criterion counts. "contradicts": the turn rejects the value as an answer.
- A document observation is one new passage stating an answer. "supports": the passage states that the value is an answer, in whole or in part. "contradicts": the passage states that the value is not an answer, or states a fact that is incompatible with it.

== Statuses ==
The status of a nugget is one of seven, from lowest to highest, read as how likely the value is a correct answer:
- "doubtful": A document contradicts the value, and no document supports it.
- "unlikely": The documents point against the value without contradicting it, for example by supporting another value of a one-answer criterion, and no document supports it.
- "unknown": No document relates to the value; only the agent's turns give it.
- "possible": The documents relate to the value but do not show that it is an answer, or they disagree on it.
- "probable": The documents show that the value is an answer only in part, only indirectly, or only by combining several documents.
- "almost certain": The documents show most of what makes the value an answer, and no document contradicts it.
- "certain": The documents show that the value is an answer, and no document contradicts it.

== Rules ==
1. Use the query to understand what each criterion asks, but record only what the turn and the passages themselves state, and judge statuses only from the sources, never from your own knowledge.
2. Think observations come from the agent's turn only, document observations from the new passages only: what a new passage states is never a think observation, since the agent has not read it.
3. Record one observation per source, criterion and value; a source may give observations on several criteria, several values, or none. A source that mentions a criterion's subject but states no answer gives no observation. When unsure, leave the observation out.
4. Record an observation also when its value is already in the belief: every source counts.
5. Record what the agent states, never whether it is right or how sure it sounds. A value the turn mentions without linking it to a criterion gives no observation.
6. A passage that gives another value for a one-answer criterion supports that value; it does not contradict the other values. A "computed" criterion gets no document observation.
7. Copy the value of a think observation exactly as the turn writes it. For a document observation, copy a value already in the belief exactly; otherwise write the value as the passage states it, as short as possible.
8. Write a belief only for each criterion with a new observation: its whole new list of nuggets, one per distinct answer of its current nuggets and new observations. Values that name the same answer in different words share one nugget, whose value is copied exactly from one of them.
9. Keep a nugget for every answer, also a rejected one; a one-answer criterion has at most 5 nuggets and a several-answers criterion at most 50, the most likely kept.
10. The evidence of a nugget lists the label of every source with an observation on its answer, supporting or contradicting it: its current sources and the new ones.
11. The nuggets of a one-answer criterion are alternatives: support for one value points against the others, and at most one of them is "almost certain" or "certain". Judge each nugget of a several-answers criterion on its own.
12. Judge statuses from the documents: the agent's turns never raise a status above "unknown", however sure the agent sounds or however often it repeats a value.
13. When unsure between two statuses, choose the one closer to "unknown".

== Output Format ==
Respond with ONLY a raw JSON object, no markdown, no code blocks, with three keys, in this order:
- "think_observations": One object per observation of the agent's turn; [] when there is none:
  - "id": The criterion id (for example "c1").
  - "stance": "supports" or "contradicts".
  - "value": The answer, copied exactly from the turn.
- "doc_observations": One object per observation of a new passage; [] when there is none:
  - "id": The criterion id.
  - "passage": The passage label (for example "d4").
  - "stance": "supports" or "contradicts".
  - "value": The answer the passage states.
  - "spans": The parts of the passage that state it, each copied exactly from one place in the passage, in its own language: the shortest part of a sentence that states the fact.
- "beliefs": One object per criterion with a new observation, in the given order; [] when there is none:
  - "id": The criterion id.
  - "reason": One sentence on what its sources show.
  - "nuggets": The whole new list, most likely first, each {"value": the answer, "status": its status, "evidence": the labels of its sources, for example ["d1", "t2"]}.
